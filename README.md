# CRM «Чистое место»

## Готовые версии и обновления

После каждого пуша в ветку `main` GitHub Actions автоматически собирает и
публикует один выпуск для обеих систем: `CRM-windows.zip` и `CRM-macos.zip`.
Список выпусков находится на странице **Releases** репозитория.

Для Windows распакуйте `CRM-windows.zip` в постоянную папку (например,
`C:\\CRM`), затем запускайте `CleanPlaceCRM.exe`. В этой же папке есть
`Обновить CRM.cmd`: двойной клик закрывает CRM, скачивает последний выпуск с
GitHub, устанавливает его поверх текущей папки и запускает обновлённую версию.
Не запускайте обновлятор прямо из ZIP-архива — сначала распакуйте его.

macOS-архив пока не подписан Apple. При первом открытии приложения macOS может
попросить подтвердить запуск в «Системные настройки → Конфиденциальность и
безопасность».

## Общие пользователи и PIN

Для работы CRM на нескольких Windows/macOS-компьютерах с общими настройками,
отдельными PIN и правами следуйте инструкции
[«Общая CRM: первый запуск и перенос ключей»](docs/COMMON_CRM_SETUP.md).
Владелец настраивает сервер и интеграции один раз; сотрудники заходят только
по личному PIN и видят лишь разрешённые им разделы.

## Запуск

```bash
flutter run -d macos
```

Google OAuth параметры передаются только через `--dart-define`:

```bash
flutter run -d macos \
  --dart-define=CRM_SHEET_ID=... \
  --dart-define=GOOGLE_CLIENT_ID=... \
  --dart-define=CRM_SYNC_ENDPOINT=https://crm.example.com/sync
```

`GOOGLE_CLIENT_ID` обязателен для кнопки «Подключить календарь». Если его не
передать, CRM не открывает страницу Google и показывает ошибку настройки.
Получите OAuth 2.0 Client ID типа **Desktop app** в Google Cloud Console →
*APIs & Services → Credentials*, включите Google Calendar API и соберите так:

```bash
flutter build macos --release \
  --dart-define=GOOGLE_CLIENT_ID=123456789012-xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx.apps.googleusercontent.com
open build/macos/Build/Products/Release/crm.app
```

Для новых клиентов Google может выдать client secret даже для Desktop app.
Если Google вернёт ошибку `client_secret is missing`, нажмите в CRM
«Добавить client secret» и вставьте секрет локально. Он хранится только в
Keychain macOS; секреты не передавайте в чат и не встраивайте в бинарник.

Шаблон переменных находится в `.env.example`; Flutter не загружает `.env`
автоматически, поэтому значения передавайте через CI или `--dart-define`.

Для Google Calendar создайте в Google Cloud OAuth-клиент типа **Desktop app**
и передайте его публичный ID. CRM использует PKCE и временный loopback
redirect. Если карточка клиента содержит secret, задайте его в CRM через
«Добавить client secret» — он сохраняется в Keychain и не попадает в
репозиторий или CI-переменные.

Для двусторонней синхронизации локальной очереди укажите HTTPS endpoint и
секрет в разделе «Настройки → Настроить защищённую синхронизацию». Токен
сохраняется в Keychain macOS и не передаётся через `--dart-define` или CI,
чтобы не попасть в готовую сборку. Endpoint принимает JSON
`{ "schemaVersion": 3, "syncToken": "…", "changes": [...] }`
и обязан вернуть `{ "acceptedIds": ["change-..."] }`. CRM удаляет из очереди
только явно подтверждённые идентификаторы; при любой ошибке запись остаётся
локально, получает счётчик попыток и может быть отправлена повторно.

### Готовый endpoint для Google Sheets

В [backend/google_apps_script/Code.gs](backend/google_apps_script/Code.gs)
находится готовый Google Apps Script. В Apps Script создайте проект, вставьте
код и в *Project settings → Script properties* задайте `CRM_SHEET_ID` и
случайный `CRM_SYNC_TOKEN`. Затем разверните проект как **Web app** с доступом
только для пользователей, которым разрешена работа с таблицей, и укажите URL
развёртывания в `CRM_SYNC_ENDPOINT` при запуске приложения.

Скрипт записывает локальные данные только в отдельные листы `CRM_*` и ведёт
`CRM_SyncAudit`, поэтому не перезаписывает существующие рабочие листы. Он
идемпотентен: повторная доставка того же `change-*` подтверждается без
повторного применения. Одновременные доставки сериализуются блокировкой Apps
Script: запросы не выполняются одновременно, но более свежий принятый снимок
может заменить предыдущий. Для нескольких одновременно работающих операторов
используйте одного писателя или вынесите разрешение конфликтов в backend. Для Apps Script секрет дополнительно находится в
HTTPS-теле запроса: web app не передаёт заголовок Authorization в `doPost`.
Endpoint принимает не более 20 изменений за запрос и снимки областей
`clients`, `stock`, `manualDeals`, `finance`, `appointments`,
`serviceCatalog`, `workspace` и `knowledgeBase`. События календаря, заметки,
планы и справочник услуг попадают в отдельные служебные листы; настройки
интеграций передаются как `auditOnly`. Неизвестный scope отклоняется, а не
отмечается успешным.

При заданном `CRM_SYNC_ENDPOINT` приложение также читает листы `Август`,
`Основное` и `Расходы` защищённым POST-запросом `operation: readSheet` с тем же
токеном. При первом запуске на новом компьютере `operation: readWorkspace`
восстанавливает снимки `CRM_*`; если на устройстве уже есть неотправленная
очередь, облачный снимок её не перезаписывает. Старый публичный gviz CSV
используется только до настройки endpoint; не публикуйте рабочую таблицу как
постоянный способ доступа.

## Проверка

```bash
flutter analyze
flutter test
```

Данные Google Sheets используют листы `Август`, `Основное` и `Расходы`.
Версия контракта и обязательные поля описаны в `lib/schema.dart`.
Импорт старого листа сделок и локальных числовых форматов вынесен в
`lib/deal_logic.dart` и покрыт отдельными тестами.
При временной недоступности таблицы показывается последняя успешная копия; локальные операции сохраняют источник и стабильный ID.
Экспорт сделок доступен в CSV и XLSX.

### Контракт таблицы и идентификаторы

Рабочие листы сохраняют совместимость с текущей таблицей:

| Лист | Минимальные поля | Назначение |
| --- | --- | --- |
| `Август` | `Авто`, `Телефон`, `Услуга`, `Работник`, `Стоимость`, `Расходы`, `Чистая прибыль` | Импорт исторических и текущих сделок |
| `Основное` | Рекомендуются `Дата`, `Выручка`, `Расходы` | Показатели для сверки с CRM |
| `Расходы` | `ID`, `Дата`, `Описание`, `Сумма` | Расходы из Google Sheets |

Защищённая синхронизация создаёт отдельные листы `CRM_Clients`,
`CRM_Stock`, `CRM_StockMovements`, `CRM_ManualDeals`,
`CRM_LocalTransactions`, `CRM_ClosedPeriods`, `CRM_Appointments`,
`CRM_ServiceCatalog`, `CRM_DashboardNotes`, `CRM_RevenuePlans`,
`CRM_KnowledgeBase`, `CRM_KnowledgeVersions` и `CRM_SyncAudit`. Они не
перезаписывают рабочие листы и являются версионированным слоем миграции на
backend. В них используются стабильные `id`: клиента, сделки, товара,
движения склада, финансовой операции и записи аудита. У клиента также
синхронизируются ID Telegram/VK для напоминаний, а у закрытого периода — все
зафиксированные финансовые части. В `CRM_ManualDeals` идентификатор сделки
хранится в последней колонке `ID`; не изменяйте его вручную.

При изменении колонок обновляйте `SheetsSchema.version`, код Apps Script и
развёртывание endpoint одновременно. Не публикуйте рабочую таблицу публично:
доступ задаётся правами Google и секретом endpoint.

Текущая схема — **версия 3**. Перед первым запуском этой версии замените код
Apps Script из репозитория и создайте новое развёртывание Web app: предыдущий
endpoint предыдущей версии намеренно отклонит очередь, чтобы не записать данные в
несовместимый контракт.

В разделе «Сообщения» доступен единый список диалогов Telegram, VK, Avito и
Instagram Direct. Для Instagram укажите ID профессионального аккаунта и токен
с правами Instagram Messaging; история открывается выбором диалога, а
неотправленные ответы автоматически попадают в локальную очередь повторной
отправки.

## Напоминания о записи

Google Calendar получает нативные popup/email-напоминания. Пока CRM открыта,
она также проверяет записи раз в минуту и за два часа отправляет уведомление в
настроенную беседу сотрудников VK. Для личного сообщения клиенту заполните в
его карточке `Telegram chat ID` или `VK peer ID`; приоритет — Telegram.

При создании записи укажите исполнителя (нескольких — через запятую). CRM
подставляет длительность услуг из настроек, хранит ID автомобиля и не даёт
пересечься времени того же исполнителя или автомобиля. Параллельные записи
разных мастеров и автомобилей разрешены; старые записи без этих привязок
консервативно блокируют наложение, пока их не отредактируют.

## Безопасность

Не коммитьте токены Avito/VK/Telegram или OAuth secrets. Для production
используйте backend-прокси и серверные секреты, а локальные копии храните в
защищённой связке ключей macOS (CRM автоматически использует secure storage).
При публикации приложения обязательно перевыпустите ранее использовавшиеся
ключи и задайте `CRM_SHEET_ID` и `GOOGLE_CLIENT_ID`
через `--dart-define` или CI-секреты.

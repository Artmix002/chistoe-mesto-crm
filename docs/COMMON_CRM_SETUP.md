# Общая CRM: первый запуск и перенос ключей

Эта настройка выполняется один раз владельцем. Сотрудники после этого знают
только свой четырёхзначный PIN: URL таблиц и ключи API им не нужны.

## 1. Разверните сервер CRM

1. Откройте [script.new](https://script.new) под рабочим Google-аккаунтом,
   у которого есть доступ к таблице и календарю CRM.
2. Замените содержимое файла кодом из
   `backend/google_apps_script/Code.gs`.
3. В **Project settings → Script properties** создайте свойства:

   | Имя | Значение |
   | --- | --- |
   | `CRM_OWNER_PIN` | Первый PIN владельца: ровно 4 цифры. После первого успешного входа скрипт сам удалит это свойство. |
   | `CRM_OWNER_NAME` | Имя первого владельца. |
   | `CRM_SHEET_ID` | ID рабочей Google Таблицы. |

4. Нажмите **Deploy → New deployment → Web app**. Выполнять от имени:
   **Me**. Доступ: **Anyone**. Скопируйте URL, оканчивающийся на `/exec`.

`Anyone` здесь нужен только для того, чтобы CRM с Windows/macOS могла открыть
Web app. Доступ к данным всё равно невозможен без действующей серверной
сессии, выданной после проверки персонального PIN.

## 2. Подключите CRM

1. Откройте CRM на компьютере владельца.
2. Нажмите на профиль внизу левого меню → **Настроить сервер CRM**.
3. Вставьте URL Web app и войдите первым владельцем по `CRM_OWNER_PIN`.
4. В **Настройки → Профили пользователей и роли** создайте ещё владельцев и
   сотрудников, каждому задав собственный PIN и уровни доступа.
5. В **Настройки → Перенести ключи в общий CRM-сервер** подтвердите перенос.
   После подтверждения ключи удаляются с данного компьютера и хранятся в
   Script Properties (`CRM_SECRETS`).

Никогда не отправляйте PIN или содержимое Script Properties в чат, почту или
GitHub. Если ключ уже был использован на чужом компьютере, перевыпустите его
в сервисе-поставщике до переноса.

## 3. Выпуски для Windows и macOS

Чтобы серверный URL сразу был в новых сборках, добавьте в GitHub repository
secret `CRM_SERVER_URL` значение URL Web app. Он не является ключом, но
собирается как секрет, чтобы не дублировать инфраструктурный URL в исходниках.
Следующий push в `main` автоматически опубликует новые Windows и macOS архивы.

Пользователь на новом компьютере открывает CRM, видит выбор пользователя и
вводит свой PIN. Ему не нужно выбирать таблицу или вводить ключи.

## Что хранится где

| Место | Данные |
| --- | --- |
| CRM на ПК | Сессионный токен, локальный кэш данных и выбранный пользователь |
| Google Apps Script | Пользователи, PIN-хэши с индивидуальной солью, права, сессии, общая конфигурация и ключи интеграций |
| Google Sheets | Рабочие CRM-данные и журнал синхронизации |

Сессия действует 30 дней и завершается при смене пользователя. При выбранном
режиме PIN не запрашивается после перезапуска, пока сессия действует: доступ к
уже открытой CRM означает работу от имени последнего пользователя.
